# AI Signal Bot (working name)

A Telegram Mini App (plus a synced PC dashboard later) that scans currency pairs, asks
Gemini to pick the strongest setup, shows an analytical **UP/DOWN** signal and tracks the
outcome.

**It never trades.** No order placement, no account control, no position sizing.
You decide and place any trade yourself.

## Status: Phase 1, market-data proof of concept

The goal of this phase is real live quotes and the latest 128 M1 candles for one pair,
checked against what Pocket Option shows. No AI, Telegram or database yet.

### About the data source (please read)

- Pocket Option has **no official public API**.
- OTC prices are generated by the broker itself. **No third-party feed can supply them.**
- This project therefore uses the community library
  [`BinaryOptionsToolsV2`](https://github.com/ChipaDevTeam/BinaryOptionsTools-v2)
  (unofficial and reverse-engineered). It may break without notice, and using it may
  conflict with the broker's terms of service.
- It authenticates with your browser **session string (SSID)**. Anyone holding the SSID
  can act as you, including trading. So:
  - use a **separate demo-only account** with no money (`PO_REQUIRE_DEMO=true` enforces this);
  - keep the SSID only in `.env`, which is git-ignored; never paste it into chat or screenshots;
  - the app reaches the library only through a **read-only whitelist proxy**
    (`app/marketdata/pocketoption.py`), and `tests/test_readonly_guard.py` checks that no
    trading or account method can be called.
- We have **not yet verified** that demo-account OTC quotes equal real-account OTC quotes.

## Setup on Windows

Install:
1. **Python 3.12** from python.org. During setup tick *"Add python.exe to PATH"*.
2. **Git for Windows**.
3. Make sure your clock is synced. In an *Administrator* PowerShell: `w32tm /resync`.

Then, in PowerShell:

```powershell
git clone https://github.com/zok111/zz.git
cd zz
git checkout phase1-market-data
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
# If activation is blocked, run once:  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
python -m pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env
```

### Getting the SSID (demo account)

1. Log in to Pocket Option in Chrome/Edge and switch to the **demo** account.
2. Press `F12` to open DevTools, open the **Network** tab, click **WS**, then reload the page (`F5`).
3. Click the WebSocket connection, open **Messages**, and find the sent message that starts
   with `42["auth",`.
4. Copy that whole message into `.env` as `PO_SSID=42["auth",{...}]` on one line, without quotes.

The SSID expires when the session ends. If the probe stops authenticating, repeat these steps.

## Run

```powershell
pytest -q                                       # unit tests (no network)
python -m app.probe                             # default asset from .env, 10 minutes
python -m app.probe --asset GBPUSD_otc --minutes 15
```

Output goes to `data/phase1/<asset>_<utc-time>/`:

| File | Content |
|---|---|
| `assets.json` | every asset the source reports (OTC flag, payout, active) |
| `history_m1.csv` | the latest 128 closed M1 candles from the source |
| `ticks.jsonl` | every live tick: raw message, source time, receive time |
| `live_m1_from_ticks.csv` | M1 candles our CandleEngine built from the ticks |
| `live_5s_from_ticks.csv` | 5-second candles (for very short expirations later) |
| `comparison_m1.csv` | our candles vs the source's candles, minute by minute |
| `chart.html` | candlestick chart (history plus live), open it in a browser |
| `summary.json` | the numbers below |

## Phase 1 verification checklist

Send me the console output, the screenshots and `summary.json`. **Never send `.env`.**

1. `pytest -q`: all tests pass.
2. **Asset list (section 1):** compare with the pair list in Pocket Option. Do OTC flags
   and payouts match?
3. **History (section 2):**
   - 128 candles;
   - `expected last ... OK`;
   - `validation : OK`, or any gaps listed explicitly;
   - the detected time offset is printed. Note it.
4. **Visual match (the key test):**
   - Open the same pair on Pocket Option with **1-minute candles**, next to `chart.html`.
   - Compare the last 10 candles' open/high/low/close digit by digit. Pocket Option shows
     your local time; the table in `chart.html` shows UTC and local time.
   - Send me a side-by-side screenshot.
5. **Live stream (section 3):**
   - a status line every 10 s with state `OK`;
   - a reasonable tick rate;
   - small `lat_p50`/`lat_p95`;
   - one `M1 closed` line each minute.
6. **Tick-built vs source candles (section 4):** how many of `N` are an exact match? Any
   differences are listed. This tells us whether our own candle building reproduces the broker's.
7. **Failure test:** during a run, turn off Wi-Fi for about 30 s.
   - The state must become `STALE` or `DISCONNECTED`, and no fake candles may appear.
   - Turn Wi-Fi back on. Does the stream recover (look for `subscribed` in the log)? Is a
     `candle_gap` reported?
8. **Stability:** one run of `--minutes 30` finishes without crashing.

We move on to the multi-pair scanner only when these checks pass.
